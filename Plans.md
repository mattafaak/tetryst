## Phase 8: Performance optimizations

| Task | Content | DoD | Depends | Status |
|------|---------|-----|---------|--------|
| 8.1 | **Offscreen canvas caching for board + grid** — The locked board (200 cells × 3 fill ops = 600 fills/frame) and grid lines (31 stroked lines/frame) are static between lock/clear events (~2-3×/second) but redrawn from scratch at 60fps. Fix: render locked board + grid onto an offscreen canvas once, then `ctx.drawImage()` each frame. Re-render offscreen canvas only on `lockPiece` or `clearLines`. Estimated impact: eliminates ~95% of per-frame fill operations. | Offscreen canvas renders board + grid once per lock/clear; `drawImage` used in hot path; no visible rendering quality regression; all tests pass | - | cc:完了 |
| 8.2 | **Cache cellSize and skip per-frame layout reads** — `calculateCellSize()` reads `devicePixelRatio`, `canvas.width`, `canvas.height` (layout-triggering) every frame (loop.ts:191). Cells size only changes on window resize. Fix: compute `cellSize` once in `start()` and update from a `resize` listener. Store result and skip per-frame call. | `calculateCellSize()` called only on resize, not per frame; rendering still responsive to window resize; all tests pass | - | cc:完了 |
| 8.3 | **Zero-allocation hot paths** — Three high-frequency functions allocate excessive temporary objects. Fix: (a) `applyGravity` (gravity.ts:36-52) creates new `Piece` per drop tick — inline collision check in the while-loop body to avoid per-tick allocations; (b) `getGhostY` (pieces.ts:100-114) creates new `Piece` per iteration — inline collision check against board directly; (c) `tickPopups` (popups.ts:14-18) allocates 2-3 arrays per frame — mutate popup timers in-place since they are ephemeral. | Hot paths produce no intermediate Piece/Position allocations in normal operation; all tests pass | - | cc:完了 |
| 8.4 | **Batch mode-timer and lock-delay state spreads** — Ultra/Sprint mode creates `{...this.state, modeTimer: ...}` every frame (loop.ts:268-280) and lock-delay creates `{...state, lockState: {...state.lockState, timer: ...}}` every grounded frame (lock-delay.ts:20-25). Fix: defer these timer updates to the next frame's immutable state mutation (e.g., fold into `applyGravity`'s state spread), or use a mutable frame-local accumulator that gets applied once per frame. | Single GameState spread per frame instead of 2-3; no behavioral change observable in gameplay; all tests pass | - | cc:完了 |
| 8.5 | **Cache buildSchedule result** — `buildSchedule(song)` is called every ~73s (each `playSongCycle`), creating 176 `NoteEvent` objects each time from a compile-time constant melody. Fix: compute once at module init and cache. | `buildSchedule` called at most once; cached schedule reused on loop; all tests pass | - | cc:完了 |
| 8.6 | **Set Vite build.target to ES2023** — `build.target` defaults to `"modules"`. Setting it to `"es2023"` (matching tsconfig) lets esbuild emit native modern syntax, slightly reducing bundle size and improving parse time. | vite.config.ts sets `build.target: "es2023"`; build outputs functionally identical; all tests pass | - | cc:完了 |
